# Диагностика и решение проблем

## Где смотреть

| Источник | Путь / команда |
|---|---|
| Журнал сервера | `C:\ProgramData\ITAM\logs\itam-ГГГГММДД.log` |
| Журнал установки | `%TEMP%\Setup Log ГГГГ-ММ-ДД #NNN.txt` (или файл из `/LOG=`) и вывод шагов настройки `C:\ProgramData\ITAM\logs\install.log` |
| Журнал PostgreSQL (встроенный) | `C:\ProgramData\ITAM\pgdata\log\` |
| Состояние служб | `sc query ITAM`, `sc query ITAM-PostgreSQL` или `services.msc` |
| Проверка сервера | `http://localhost:8080/health` → `{"status":"Healthy","database":true,"version":"…"}` (503 `Degraded` — нет связи с БД) |
| Подключение к БД | `"C:\Program Files\ITAM\ITAM.Server.exe" check` |
| Версия и пути | **Администрирование → О системе** или `ITAM.Server.exe version` |
| Журнал Windows | `eventvwr` → Журналы Windows → Приложение / Система (ошибки запуска служб) |

## Типичные проблемы

### Страница не открывается с других компьютеров
1. На сервере откройте `http://localhost:8080/health`. Не открывается — см. «Служба не запускается».
2. Открывается локально, но не по сети — проверьте правило брандмауэра:
   `netsh advfirewall firewall show rule name="ITAM Web"`; добавить:
   `netsh advfirewall firewall add rule name="ITAM Web" dir=in action=allow protocol=TCP localport=8080`.
3. Проверьте, что сервер слушает все интерфейсы: в `itam.json` `"Server": { "Urls": "http://0.0.0.0:8080" }`.

### Служба ITAM не запускается / сразу останавливается
* Порт занят: `netstat -ano | findstr :8080` → смените порт в `itam.json` (`Server:Urls`) и правило брандмауэра.
* Нет подключения к БД: `ITAM.Server.exe check`. Сервер стартует и без БД (повторяет подключение каждые 30 с),
  а `/health` отвечает `503 Degraded` с `"database": false`.
* Запустите сервер в консоли от имени администратора, чтобы увидеть ошибку:
  `sc stop ITAM` → `"C:\Program Files\ITAM\ITAM.Server.exe"` → читать вывод → `Ctrl+C` → `sc start ITAM`.

### Встроенный PostgreSQL не запускается
* `sc query ITAM-PostgreSQL`; журнал `C:\ProgramData\ITAM\pgdata\log`.
* Порт 5433 занят другим PostgreSQL — перерегистрируйте службу с другим портом и исправьте `Port` в строке подключения
  `itam.json`:
  ```bat
  cd "C:\Program Files\ITAM\pgsql\bin"
  pg_ctl unregister -N ITAM-PostgreSQL
  pg_ctl register -N ITAM-PostgreSQL -U "NT AUTHORITY\NetworkService" -D C:\ProgramData\ITAM\pgdata -S auto -o "-p 5434 -c listen_addresses=localhost -c logging_collector=on"
  sc start ITAM-PostgreSQL
  ```
* Нет прав у `NETWORK SERVICE` на папку `pgdata`:
  `icacls C:\ProgramData\ITAM\pgdata /grant "*S-1-5-20:(OI)(CI)F" /T`.

### Установщик сообщил об ошибке «Первичная настройка ITAM завершилась с ошибкой»
Откройте журнал установки — там вывод `ITAM.Server.exe setup`. Частые причины: неверный пароль PostgreSQL,
у пользователя нет права `CREATEDB`/`CREATEROLE`, сервер PostgreSQL недоступен по сети (`pg_hba.conf`, брандмауэр).
Исправьте и повторите установку — шаги идемпотентны (существующая база и роль используются повторно).

### Забыт пароль администратора / учётная запись заблокирована
```bat
"C:\Program Files\ITAM\ITAM.Server.exe" reset-admin --user admin --password "НовыйПароль123"
```
Команда сбрасывает пароль, снимает блокировку и назначает роль суперадминистратора. Блокировку другого пользователя
снимает администратор: **Пользователи → Разблокировать**.

### «Недействительный CSRF-токен», «Сессия устарела»
Обновите страницу (F5). Если повторяется — проверьте, что прокси не удаляет cookie и не меняет домен; при доступе по
HTTP не включайте `Security:RequireHttpsCookies`.

### Операция отклонена: «Актив уже выдан», «Конфликт с историей актива»
Это защита целостности истории. Откройте карточку актива → **История**, посмотрите события вокруг нужной даты.
Для внесения прошлой выдачи, которая уже завершилась, используйте «Историческую выдачу» с датой возврата
(см. ADMIN_GUIDE §7). Ошибочную операцию отмените (право `assets.correct`), затем внесите правильную.

### «Данные были изменены другим пользователем»
Запись изменили параллельно. Обновите страницу и повторите действие.

### PDF не формируется или выглядит иначе, чем DOCX
* Без LibreOffice работает встроенный движок (упрощённая вёрстка). Для точной копии установите LibreOffice и укажите
  путь к `soffice.exe` в **Настройки → Документы** (движок «Автоматически» или «LibreOffice»).
* Если LibreOffice зависает — проверьте, что он запускается под учётной записью службы (первый запуск создаёт профиль);
  временно выберите движок «Встроенный».
* В шаблоне остались `{{...}}` — плейсхолдер написан с ошибкой: при загрузке версии шаблона система показывает
  неизвестные плейсхолдеры.

### Резервное копирование: «Не найден pg_dump.exe»
Укажите каталог утилит PostgreSQL в `itam.json`: `"Backup": { "PgBinPath": "C:\\Program Files\\PostgreSQL\\16\\bin" }`
и перезапустите службу. Версия `pg_dump` должна быть не ниже версии сервера.

### Ошибка копирования в сетевую папку
Служба работает от `LocalSystem`; выдайте право записи учётной записи компьютера (`ДОМЕН\ИМЯСЕРВЕРА$`) на сетевую папку.

### Камера не включается при инвентаризации
Браузеры разрешают камеру только на HTTPS или `localhost`. Настройте HTTPS (INSTALLATION.md §9) или используйте USB/
Bluetooth-сканер штрихкодов (работает как клавиатура — просто сканируйте в поле ввода).

### QR-код ведёт на неправильный адрес
Укажите **Настройки → Общие → Адрес сервера** (например `http://itam.company.local:8080`) и перепечатайте этикетки.

### Медленная работа
* Проверьте ресурсы сервера и размер базы (DATABASE.md → Обслуживание).
* Большие списки фильтруйте; экспорт тяжёлых отчётов выполняйте вне часов пик.
* Журнал сервера содержит предупреждения о медленных запросах (`Microsoft.EntityFrameworkCore`).

### Обновление завершилось ошибкой миграции
Служба остаётся остановленной, данные не изменены (миграции выполняются в транзакции). Восстановите предыдущую версию
установщиком или исправьте причину (журнал) и выполните `ITAM.Server.exe migrate`. При необходимости — восстановление из
копии (BACKUP.md).

## Сбор информации для поддержки

1. Версия (`ITAM.Server.exe version`), ОС, способ установки (встроенный/внешний PostgreSQL).
2. Журнал сервера за день проблемы и журнал установки.
3. Точное время, пользователь, действие, текст ошибки (в уведомлении об ошибке есть код, например `TEMPORAL_CONFLICT`).
Не отправляйте файлы `config\itam.json`, `keys\` и резервные копии — они содержат пароли и ключи шифрования.
