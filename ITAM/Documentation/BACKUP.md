# Резервное копирование и восстановление

## Что входит в резервную копию

Один архив `itam-backup-ГГГГММДД-ЧЧммсс.zip`:

| Файл в архиве | Содержимое |
|---|---|
| `database.dump` | база данных PostgreSQL (`pg_dump`, custom format) |
| `storage/` | документы, сканы, вложения, фото, шаблоны DOCX (если включено «Включать файлы») |
| `keys/` | ключи шифрования (без них не расшифровать лицензионные ключи и пароль SMTP) |
| `manifest.json` | версия ITAM, дата, состав, размеры |

Для каждой копии сохраняется размер и SHA-256. Архив содержит конфиденциальные данные — храните его в защищённом месте.

## Автоматическое копирование

**Администрирование → Настройки → Резервное копирование:**
* расписание — ежедневно или еженедельно (день недели), время (часовой пояс организации), по умолчанию ежедневно в 02:00;
* папка — по умолчанию `C:\ProgramData\ITAM\backups`; можно указать сетевую папку `\\server\share\itam`
  (у учётной записи службы ITAM — `LocalSystem`, т.е. компьютер `ДОМЕН\СЕРВЕР$` — должно быть право записи);
* срок хранения в днях и максимальное количество копий — старые копии удаляются автоматически
  (последняя успешная копия не удаляется никогда);
* включать файлы.

Планировщик проверяет расписание каждые 5 минут. Ошибка копирования создаёт критическое уведомление.

## Ручное копирование

* **Администрирование → Резервные копии → Создать резервную копию**; готовый архив можно скачать.
* Командная строка (например, из Планировщика заданий Windows перед обслуживанием сервера):
  ```bat
  "C:\Program Files\ITAM\ITAM.Server.exe" backup --out D:\Backups\ITAM
  ```

Рекомендуется копировать архивы на другой сервер или носитель (правило 3-2-1).

## Восстановление

> Восстановление полностью заменяет текущую базу данных и файлы. Перед восстановлением ITAM **автоматически создаёт
> страховочную копию** текущего состояния (тип «Перед восстановлением»).

### Из веб-интерфейса
**Администрирование → Резервные копии** → у нужной копии «Восстановить» (или «Восстановить из файла» — загрузить архив).
Нужно право `backup.restore`. После восстановления страница перезагрузится; пользователям потребуется войти заново.

### Из командной строки (если веб-интерфейс недоступен)
```bat
sc stop ITAM
"C:\Program Files\ITAM\ITAM.Server.exe" restore D:\Backups\itam-backup-20261001-020000.zip --yes
sc start ITAM
```
После восстановления автоматически применяются миграции, если копия сделана в более старой версии ITAM.

## Перенос на новый сервер

1. На старом сервере создайте резервную копию (с файлами) и скопируйте архив.
2. На новом сервере установите ITAM той же или более новой версии (`ITAM-Setup.exe`).
3. Восстановите архив (веб-интерфейс или CLI, см. выше).
4. Проверьте **Настройки → Общие → Адрес сервера** (используется в QR-кодах) и при необходимости перепечатайте этикетки.
5. Остановите службу ITAM на старом сервере.

## Проверка копий

Раз в квартал восстанавливайте последнюю копию на тестовом сервере (или в Docker) и проверяйте: вход, карточки активов,
открытие документов, просмотр лицензионного ключа (проверка ключей шифрования).

## Требования

`pg_dump` и `pg_restore` берутся из встроенного PostgreSQL (`C:\Program Files\ITAM\pgsql\bin`), из параметра
`Backup:PgBinPath` в `itam.json`, из `C:\Program Files\PostgreSQL\*\bin` или из `PATH`. Версия утилит должна быть не ниже
версии сервера PostgreSQL.
