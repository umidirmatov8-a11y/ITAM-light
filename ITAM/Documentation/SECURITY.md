# Безопасность ITAM

## Реализованные меры

### Аутентификация и сессии
* Пароли хранятся только в виде хеша PBKDF2 (ASP.NET Core Identity v3, HMAC-SHA512, соль, 100 000+ итераций);
  при входе устаревшие хеши автоматически перехешируются.
* Политика паролей: минимальная длина (10), заглавные/строчные буквы, цифры, спецсимволы (настраивается), срок действия,
  принудительная смена при первом входе и после сброса.
* Блокировка учётной записи после N неудачных попыток (по умолчанию 5) на M минут (15); все неудачные входы — в аудите и
  на главной (плитка «Неудачные входы за 24 ч»).
* Сессия — серверная запись `UserSessions`; в браузере только защищённый идентификатор (cookie `itam.sid`,
  `HttpOnly`, `SameSite=Strict`, `Secure` при HTTPS). Тайм-аут бездействия (60 мин) и максимальная длительность (12 ч);
  администратор может завершить любую сессию; сброс пароля администратором, отключение и удаление пользователя завершают его сессии.
* API-токены: хранится только SHA-256 хеш, показывается один раз, срок действия, отзыв.

### Авторизация
* Ролевая модель с детальными правами; **каждый метод API проверяет права на сервере**.
* Ограничение по регионам применяется ко всем запросам и операциям (в т.ч. к назначению в чужой регион).
* Право «своё подразделение» для руководителей.
* Защита от эскалации: нельзя выдать роль/право, которых нет у себя; нельзя отключить последнего суперадминистратора.

### Веб-безопасность
* CSRF: double-submit token (cookie `XSRF-TOKEN` → заголовок `X-XSRF-TOKEN`) для всех изменяющих запросов с cookie-сессией.
* Заголовки: `Content-Security-Policy` (`script-src 'self'`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`; HSTS — параметром `Security:UseHsts=true` (при работе по HTTPS).
* XSS: React экранирует вывод, HTML из данных не вставляется.
* SQL-инъекции: только параметризованные запросы EF Core/Npgsql.
* Ограничение частоты: вход — 10/мин с IP, API — 1200/мин на пользователя.
* Загрузка файлов: белый список расширений, лимит размера, имена файлов на диске генерируются системой, выдача с
  `Content-Disposition: attachment` и `nosniff`; файлы проверяются на соответствие правам объекта, к которому прикреплены.
* Экспорт CSV/XLSX: значения, начинающиеся с `= + - @`, экранируются (защита от CSV/формульных инъекций).
* Ошибки: клиент получает код и понятное сообщение без стека и SQL; подробности — только в журнале сервера.

### Данные
* Лицензионные ключи, пароль SMTP и токен Telegram шифруются (ASP.NET Data Protection, AES-256-CBC + HMAC).
  Ключи шифрования — `C:\ProgramData\ITAM\keys`, входят в резервную копию. Ключи лицензий показываются только при праве
  `licenses.keys.view`, каждый просмотр пишется в аудит.
* Журнал аудита неизменяем на уровне БД (триггеры запрещают UPDATE/DELETE/TRUNCATE). Пароли, хеши и токены в аудит не
  попадают (поля помечены `[Sensitive]` и маскируются).
* Приложение подключается к PostgreSQL под ролью `itam` без прав суперпользователя; встроенный PostgreSQL слушает только
  `localhost`, аутентификация `scram-sha-256`.
* Папка `C:\ProgramData\ITAM\config` (строка подключения) доступна только SYSTEM и администраторам.
* Публичная карточка по QR показывает только разрешённые в настройках поля (без ФИО и финансов).

## Рекомендации по эксплуатации

1. **Включите HTTPS** (обратный прокси или сертификат в Kestrel, см. INSTALLATION.md §9) и `Security:RequireHttpsCookies=true`.
2. Не публикуйте ITAM в интернет; при необходимости — только через VPN/прокси с дополнительной аутентификацией.
3. Ограничьте брандмауэром доступ к порту 8080 сетями пользователей; порт 5433 встроенного PostgreSQL наружу не открыт.
4. Используйте персональные учётные записи; суперадминистраторов — минимум (2 человека).
5. Регулярно проверяйте журнал аудита (неудачные входы, просмотр ключей, изменения ролей и настроек).
6. Храните резервные копии вне сервера: архив содержит базу и ключи шифрования — ограничьте к нему доступ.
7. Устанавливайте обновления ITAM и Windows; PostgreSQL обновляется вместе с установщиком ITAM.
8. Отключите Swagger UI, если он не нужен: `"Server": { "EnableSwagger": false }`.
9. Для интеграций выдавайте API-токены отдельных технических пользователей с ролью «Только чтение» или нужным минимумом прав.

## Сообщение об уязвимости

Опишите проблему, шаги воспроизведения и версию (`ITAM.Server.exe version` или **Администрирование → О системе**)
и передайте администратору системы / ответственному за ИБ организации. Не публикуйте детали до исправления.
