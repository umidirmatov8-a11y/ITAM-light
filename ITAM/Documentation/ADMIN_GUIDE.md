## 1. Интерфейс

* **Левое меню** — разделы, доступные по правам пользователя. **Верхняя панель** — глобальный поиск (инвентарный и серийный
  номер, ФИО, табельный номер, номер документа; точное совпадение инвентарного номера сразу открывает карточку),
  «Быстрые действия» (добавить сотрудника/актив, выдать, принять, передать, ремонт, документ), уведомления, тема, язык, профиль.
* **Таблицы**: сортировка по колонке, фильтры, поиск, выбор колонок (настройка запоминается в браузере), постраничный
  вывод, экспорт XLSX/CSV, выбор строк для массовых действий.
* **Даты** отображаются в часовом поясе организации (по умолчанию Asia/Tashkent) в формате `ДД.ММ.ГГГГ ЧЧ:мм`;
  в базе хранятся в UTC.
* Языки: русский (по умолчанию), English, O'zbekcha (непереведённые строки показываются по-русски).

## 2. Пользователи, роли, регионы

**Администрирование → Пользователи.** Учётная запись: логин, имя, email, роли, регионы (или «все регионы»), связанный
сотрудник, язык, флаг «сменить пароль при входе». Действия: сброс пароля, разблокировка, отключение, список активных
сессий и их завершение.

Защита: нельзя отключить/удалить последнего суперадминистратора и нельзя выдать права, которых нет у вас самого.

**Роли и права.** Встроенные роли (можно изменять, кроме суперадминистратора):

| Роль | Назначение |
|---|---|
| Суперадминистратор | все права |
| IT-администратор | активы, сотрудники, справочники, пользователи, шаблоны, настройки |
| Менеджер IT-активов | учёт активов, операции, ремонты, инвентаризация, склад, договоры |
| Helpdesk | выдача/возврат, ремонты, просмотр |
| Информационная безопасность | доступы, лицензии, аудит |
| Руководитель подразделения | просмотр сотрудников и техники **своего подразделения** (право `scope.own-department`) |
| Аудитор | просмотр всех данных, журнал аудита, отчёты |
| Только чтение | просмотр основных разделов |

Права имеют вид `модуль.действие`: `employees.view`, `employees.create`, `employees.terminate`, `assets.assign`,
`assets.return`, `assets.transfer`, `assets.repair`, `assets.status`, `assets.backdate` (операции задним числом),
`assets.correct` (отмена операций), `assets.finance.view`, `licenses.keys.view`, `documents.generate`, `documents.sign`,
`documents.templates.manage`, `reports.view`, `import.run`, `export.run`, `audit.view`, `users.manage`, `roles.manage`,
`settings.manage`, `backup.manage`, `backup.restore` и др. — полный список на странице роли.
**Все права проверяются на сервере**; скрытие кнопок в интерфейсе — только удобство.

**Регионы.** Пользователь с ограничением по регионам видит и изменяет только объекты своих регионов (сотрудники, активы,
операции, ремонты, локации, подразделения, лицензии с регионом); передать актив в чужой регион нельзя.

**Профиль → API-токены** — персональные токены для интеграций (действуют с правами владельца, отзываются).

## 3. Справочники и дополнительные поля

**Администрирование → Справочники**: регионы, локации (иерархия: город → филиал → офис → здание → этаж → кабинет, склады),
подразделения (иерархия), должности, статусы сотрудников, категории и типы активов (префикс инвентарного номера,
обязательность серийного номера, срок службы), статусы активов, производители, поставщики/сервисные центры, статусы ремонта,
номенклатура склада, каталог ПО, типы лицензий, системы и уровни доступа.

* Статусы привязаны к **системной категории** (На складе, Выдан, В ремонте, Списан…) — бизнес-правила работают по
  категории, поэтому статусы можно переименовывать и добавлять свои.
* Записи не удаляются, а **архивируются** — старые документы и история продолжают показывать прежние названия.
  В документах и истории сохраняется снимок данных на дату операции.

**Администрирование → Дополнительные поля**: поля для сотрудников, активов (для всех или для конкретного типа), лицензий,
ПО, ремонтов, доступов, подразделений, локаций. Типы: текст, многострочный текст, число, дата, дата и время, да/нет, список,
множественный выбор, URL, email, сумма. Настройки: обязательность, участие в поиске, показ в списке, группа, значение по
умолчанию, подсказка. Поля доступны в шаблонах документов (`{{Asset.Custom.<ключ>}}`), импорте и экспорте.

## 4. Сотрудники

* Карточка: ФИО, табельный номер (генерируется), должность, подразделение, регион, офис, кабинет, руководитель,
  контакты, логин, даты приёма/увольнения, фото, дополнительные поля. Вкладки: Обзор, Техника, Лицензии, Доступы,
  Документы, Чек-листы, История оргструктуры, Хронология, Файлы, Аудит.
* **Перевод** (смена подразделения/должности/региона) сохраняется с датой вступления в силу; отчёты на прошлые даты
  показывают прежнее место работы.
* **Увольнение**: система показывает незакрытые позиции — выданная техника, лицензии, активные доступы, открытые ремонты,
  неподписанные документы, открытые чек-листы. Уволить с незакрытыми позициями можно только с явным подтверждением.
* Удаление возможно только для сотрудника без истории; иначе — архив.
* Массовые действия: смена подразделения, должности, региона, статуса, архивирование.

## 5. Активы

* Инвентарный номер генерируется по формату (по умолчанию `{PREFIX}-{SEQ:6}` → `LPT-000123`) или вводится вручную
  (проверяется уникальность). Счётчики атомарны и не повторяются при одновременной работе.
* Карточка `/assets/{id}`: вкладки Обзор, Хронология, История, Выдачи, Ремонты, Документы, Лицензии, Файлы, Аудит;
  кнопки Выдать / Принять / Передать / В ремонт / Изменить / Сформировать документ / Печать QR.
* **Дата постановки на учёт** — для давно используемой техники укажите фактическую дату: история начнётся с неё.
* **QR-код** ведёт на `http(s)://адрес-сервера/assets/{id}`; без входа показывается краткая карточка (что именно — настраивается),
  полная — после входа. **Печать этикеток** — PDF с QR, штрихкодом Code128, инвентарным номером и названием.
* Финансы (при праве `assets.finance.view`): цена, поставщик, договор, счёт, гарантия, амортизация (линейная или
  уменьшаемого остатка), остаточная стоимость.
* Комплектующие: актив может входить в состав другого (системный блок → видеокарта).

## 6. Операции

Все операции оформляются **актами** с номерами (`ISS-000001` выдача, `RET-` возврат, `TRF-` передача, `STC-` смена статуса)
и могут сразу сформировать документ.

* **Выдача** — сотрудник, один или несколько активов (поиск по номеру/серийному/названию или сканером), дата и время,
  место, ответственный, состояние, комплектация, комментарий, плановая дата возврата (временная выдача). Выдать можно
  только актив в статусе «На складе» или «Зарезервирован» и не числящийся за другим сотрудником.
* **Возврат** — сотрудник, затем его техника; по каждому активу: состояние, комплектация, повреждения, недостающее;
  место хранения; «сразу отправить в ремонт».
* **Передача** — другому сотруднику, в подразделение, локацию или регион, с причиной.
* **Смена статуса** — резерв (для кого, до какой даты), утеря, кража, списание, утилизация (способ). Списанный актив может
  восстановить только пользователь с правом исправлений.
* Карточка операции: снимок данных сотрудника и активов на момент операции, подпись (статус, способ, дата, скан), документы.

Одновременные операции защищены: если два пользователя одновременно выдают один актив, успешной будет только одна
выдача, второй получит сообщение о конфликте.

## 7. Операции задним числом и исправления

Каждое событие актива хранит **фактическую дату** (когда произошло) и **дату внесения** (когда записано), а также автора.

* Операцию можно внести с датой в прошлом. Если дата старше допуска (`Настройки → Безопасность → разрешено задним числом
  без спец. права`, по умолчанию 24 ч), нужно право `assets.backdate`. Такие операции помечены «Задним числом».
* Система пересчитывает всю историю актива по фактическим датам и **отклоняет** операцию, если она противоречит
  последующим событиям, например:
  * актив выдан Петрову 03.10, пытаемся выдать Иванову 01.10 без возврата — ошибка «Актив уже выдан»;
  * правильно: «Историческая выдача» Иванову 01.10 с датой возврата 02.10 — обе записи проверяются вместе;
  * операция раньше даты постановки на учёт — ошибка.
* **Состояние на дату** (карточка актива → История) показывает, у кого был актив в любой момент. Отчёт «Состояние активов
  на дату» строится так же.
* **Отмена операции** (право `assets.correct`): операция не удаляется, а помечается отменённой с причиной; история
  пересчитывается, проверяется согласованность последующих событий.

## 8. Ремонты

Создание из карточки актива или раздела «Ремонты»: проблема, сервисный центр, мастер, гарантийный ремонт, стоимость,
плановая дата возврата. Этапы: Создан → Отправлен → Диагностика → Ремонт → Ожидание запчастей → Завершён → Возвращён
(или Отменён). Пока актив в ремонте, выдать его нельзя. При возврате выбирается статус после ремонта. Просроченные ремонты
попадают в уведомления и на главную.

## 9. Лицензии, ПО, доступы

* **Лицензии**: ПО, вендор, тип и модель (на пользователя, на устройство, подписка, бессрочная, корпоративная,
  конкурентная, на площадку), количество мест, ключ (хранится зашифрованным, показ — по праву `licenses.keys.view`
  с записью в аудит), сроки, стоимость, договор, регион. Назначение сотруднику или устройству; превышение мест
  запрещено; назначение истёкшей лицензии — только с подтверждением. Сводка: всего/занято/свободно/истекло.
* **Каталог ПО**: издатель, версия, требует лицензии.
* **Доступы**: система (AD, почта, VPN, 1С, CRM…), уровень/роль, учётная запись, заявка, дата выдачи/отзыва, пересмотр
  (интервал задаётся у системы). Отдельный фильтр — доступы уволенных сотрудников.

## 10. Онбординг и оффбординг

**Администрирование → Шаблоны чек-листов**: пункты с типом действия (вручную, выдать технику типа…, выдать доступ,
назначить ПО, подписать документы, вернуть всю технику, отозвать все доступы, отозвать лицензии, закрыть ремонты,
сформировать документ), обязательность, срок в днях, применимость к подразделению/должности.

Чек-лист запускается при создании сотрудника (онбординг), при увольнении (оффбординг) или вручную. Автоматические пункты
проверяются системой (например, «вся техника возвращена» отмечается сам, когда у сотрудника не осталось техники).

## 11. Шаблоны документов

**Администрирование → Шаблоны документов.** Шаблон = тип документа + версии DOCX. Загрузка новой версии не меняет ранее
сформированные документы — они хранят ссылку на версию шаблона и все подставленные значения.

1. Создайте документ в Word, вставьте плейсхолдеры в фигурных скобках, например `{{Employee.FullName}}`.
2. Для таблицы техники создайте строку таблицы с плейсхолдерами `{{Item.*}}` — она повторится для каждого актива.
3. Загрузите DOCX: система покажет найденные и **неизвестные** плейсхолдеры (опечатки).
4. Сделайте версию активной; при необходимости назначьте шаблон шаблоном по умолчанию для типа документа.

Основные плейсхолдеры (полный список с описаниями — на странице шаблона):

| Группа | Плейсхолдеры |
|---|---|
| Организация, документ | `Organization.Name`, `Document.Number`, `Document.Date`, `Current.Date`, `Current.User` |
| Сотрудник (на дату операции) | `Employee.FullName`, `ShortName`, `EmployeeNumber`, `Department`, `DepartmentPath`, `Position`, `Region`, `Location`, `Room`, `Email`, `Phone`, `Login`, `Manager`, `Custom.<ключ>` |
| Актив (первый) | `Asset.InventoryNumber`, `SerialNumber`, `Manufacturer`, `Model`, `Name`, `Type`, `Price`, `Custom.<ключ>` |
| Операция | `Operation.Number`, `Type`, `EffectiveDate`, `EffectiveDateTime`, `RecordedAt`, `RecordedBy`, `Comment`, `Location`, `AssetCount`, `Reason`; `Issue.Date`, `Issue.ResponsiblePerson`, `Return.Date`, `Transfer.Date` |
| Ответственный | `Responsible.FullName`, `Responsible.Position` |
| Строка таблицы | `Item.Index`, `InventoryNumber`, `Name`, `SerialNumber`, `Manufacturer`, `Model`, `Type`, `Condition`, `Accessories`, `Damage`, `MissingItems`, `From`, `To`, `Price` |
| Ремонт, инвентаризация | `Repair.*`, `Inventory.*` (для соответствующих типов документов) |

Плейсхолдеры, набранные в Word с разным форматированием внутри (Word разбивает текст на фрагменты), распознаются корректно.

**Генерация**: после операции («Сформировать документ»), из карточки или раздела «Документы». Результат — DOCX и PDF.
PDF создаётся через LibreOffice, если он установлен (точная копия DOCX; путь к `soffice.exe` — в настройках), иначе
встроенным движком. Реестр документов: номер, тип, сотрудник, версия шаблона, подпись, скан, аннулирование.

## 12. Инвентаризация, склад, договоры

* **Инвентаризация**: создайте кампанию (регион, локация с вложенными, подразделение) — система сформирует список
  ожидаемых активов. Сканируйте QR/штрихкоды USB-сканером или камерой телефона, отмечайте фактическое местоположение.
  Результаты: Найдено, Не на месте, Не найдено, Неучтённый. Завершение отмечает непроверенные позиции как «Не найдено»;
  формируется акт инвентаризации.
* **Склад расходников**: номенклатура (артикул, единица, минимальный остаток), поступление, выдача сотруднику или для
  ремонта актива, перемещение между складами, корректировка по факту; остатки по складам; предупреждение о малом остатке.
* **Договоры**: номер, тип (поставка, аренда, обслуживание, лицензионный, поддержка), поставщик, сроки, сумма, файлы;
  связи с активами и лицензиями; предупреждение об окончании.

## 13. Отчёты, импорт, экспорт

**Отчёты** (просмотр на экране + экспорт XLSX/CSV/PDF): инвентарная ведомость, состояние активов на дату, оборудование
сотрудников, активы по регионам, активы по подразделениям, движение активов, ремонты, лицензии, соответствие
лицензированию, доступы, оффбординг, гарантия, амортизация, журнал аудита. Фильтры: регион, подразделение, тип, статус,
период и др.

**Импорт** (сотрудники, активы, подразделения, локации): скачайте шаблон → загрузите XLSX/CSV → просмотр → сопоставление
колонок с полями → проверка (ошибки по строкам и колонкам, сколько записей будет создано/обновлено) → подтверждение.
Опции: обновлять существующие (по табельному/инвентарному номеру), создавать недостающие значения справочников,
пропускать строки с ошибками. Импорт без проверки невозможен.

**Экспорт** любой таблицы — кнопка «Экспорт». Значения, начинающиеся с `= + - @`, экранируются (защита от формул в Excel).

## 14. Уведомления

Проверки выполняются ежечасно (и по кнопке «Проверить сейчас»): истечение лицензий и гарантии, окончание договоров,
превышение мест лицензий, просроченные ремонты и временные выдачи, техника у уволенных, активы без ответственного,
пересмотр доступов, доступы уволенных, малый остаток на складе, ошибки резервного копирования. Каналы: колокольчик в
интерфейсе, email (SMTP), Telegram-бот. Получатели — пользователи с правом просмотра уведомлений в своих регионах и
адреса из настроек.

## 15. Настройки

| Группа | Параметры |
|---|---|
| Общие | название организации, логотип, часовой пояс, язык, валюта, формат даты, адрес сервера для QR и ссылок |
| Нумерация | форматы номеров активов, актов, ремонтов, документов, инвентаризаций, табельных номеров |
| Документы | движок PDF (авто/LibreOffice/встроенный), путь к LibreOffice, PDF вместе с DOCX, требовать подпись |

| Безопасность | политика паролей, блокировка после неудачных попыток, тайм-аут сессии, срок пароля, допуск «задним числом» |
| Резервное копирование | расписание (ежедневно/еженедельно, время), папка (локальная или сетевая), срок хранения и количество копий, включать файлы |
| QR | что показывать без входа |

Пароли SMTP и токен Telegram хранятся зашифрованными и в интерфейсе отображаются как `********`.

## 16. Журнал аудита

Записываются: входы и выходы (в т.ч. неудачные), создание/изменение/удаление/архивирование любых записей (с прежними и
новыми значениями), операции, документы, просмотр лицензионных ключей, изменения прав и настроек, резервное копирование и
восстановление, импорт. Для каждой записи: время, пользователь, IP-адрес, браузер, действие, объект, результат.
Журнал **неизменяем**: изменение и удаление записей запрещено на уровне базы данных (триггер). Фильтры и экспорт — в разделе
«Журнал аудита»; у каждого объекта есть вкладка «Аудит».

## Регламентные задачи администратора

* Ежедневно: уведомления на главной (просроченные ремонты, техника уволенных, истекающие лицензии).
* Еженедельно: проверка успешности резервного копирования (**Резервные копии**), копия на внешний носитель/сервер.
* Ежеквартально: пересмотр доступов, инвентаризация, проверка ролей пользователей, тестовое восстановление на отдельном
  сервере (см. [BACKUP.md](BACKUP.md)).
