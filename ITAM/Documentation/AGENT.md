# Агент инвентаризации для Windows

Агент сам собирает данные компьютера и отправляет их в ITAM. Компьютер появляется в разделе **Оборудование → Агенты**,
связывается с активом (или актив создаётся автоматически), а характеристики актива поддерживаются в актуальном состоянии.

## Что собирается

| Группа | Данные |
|---|---|
| Компьютер | имя, домен, производитель, модель, серийный номер (BIOS), UUID, тип корпуса (ноутбук / системный блок / моноблок / сервер / виртуальная машина) |
| Оборудование | процессор и число ядер, объём памяти, физические диски (модель, тип HDD/SSD/NVMe, объём, серийный номер), тома и свободное место, видеокарты, мониторы (модель и серийный номер), принтеры |
| Сеть | адаптеры, MAC, IP-адреса, шлюзы, DHCP |
| Система | Windows (редакция, версия 23H2 и т.п., сборка, разрядность), дата установки, последняя загрузка, версия BIOS, антивирус (Центр безопасности Windows) |
| Пользователь | вошедший пользователь `ДОМЕН\логин` — сопоставляется с сотрудником ITAM по полю «Логин (AD)» |
| Программы | установленные программы (название, версия, издатель, дата установки) — из реестра, без обновлений Windows и системных компонентов |

Не собираются: файлы и документы пользователей, история браузера, пароли, содержимое экрана.

## Как это работает

```
 Компьютер (SYSTEM, задача «ITAM Agent»)                 Сервер ITAM
 ───────────────────────────────────────                 ──────────────────────────────────────────────
 1. первый запуск: POST /api/agent/register  ───────▶  проверка ключа регистрации → выдаёт токен устройства
    (ключ регистрации, MachineGuid, имя)                (хранится только SHA-256 токена)
 2. POST /api/agent/inventory  (X-ITAM-Agent-Token) ─▶  сохраняет данные и список ПО
                                                       ├ ищет актив по серийному номеру, затем по имени компьютера
                                                       ├ нет совпадения → создаёт актив (если задан регион)
                                                       └ обновляет у актива имя, IP, MAC, процессор, память, диски, ОС
                                                         и пишет изменения в историю актива
```

* Агент — сценарий PowerShell (`ITAM-Agent.ps1`): работает в Windows 10/11 и Windows Server 2016+ без установки
  дополнительных программ (используется встроенный Windows PowerShell 5.1).
* Задача планировщика «ITAM Agent» от имени SYSTEM запускается при загрузке (через 3 мин), при входе пользователя
  (через 1 мин) и каждый час. Отправка происходит, если прошёл интервал (по умолчанию 4 ч, задаётся на сервере или
  в GPO) или сменился вошедший пользователь.
* Первый отчёт отправляется сразу при установке — компьютер появляется в ITAM через несколько секунд.
* Токен устройства хранится в `C:\ProgramData\ITAM Agent\state.json` (доступ только SYSTEM и администраторам).
  Если токен отозван (компьютер удалён в ITAM), агент регистрируется заново с ключом регистрации.

## Установка

Пакет агента: **Агенты → Установка → Скачать пакет агента** (с адресом сервера и ключом внутри) или
`http://СЕРВЕР:8080/api/agent/package` (без ключа — для GPO). Пакет также лежит на сервере в
`C:\Program Files\ITAM\agent`.

Состав пакета:

| Файл | Назначение |
|---|---|
| `ITAM-Agent.ps1` | сбор и отправка данных |
| `Install-ITAMAgent.ps1`, `install.cmd`, `uninstall.cmd` | установка, обновление, удаление |
| `agent.config.json` | адрес сервера и ключ (только в пакете, скачанном администратором) |
| `PolicyDefinitions\ITAM.admx`, `ru-RU\ITAM.adml`, `en-US\ITAM.adml` | шаблоны групповой политики |
| `README.txt` | краткая инструкция |

### Вручную (один компьютер)

1. Скачайте пакет в ITAM, распакуйте на компьютере.
2. Запустите `install.cmd` от имени администратора.

Без скачивания архива вручную — одной командой из окна администратора (готовая команда с вашим адресом и ключом есть на
вкладке «Установка»):

```bat
powershell -NoProfile -ExecutionPolicy Bypass -Command "$p=Join-Path $env:TEMP 'itam-agent'; iwr -UseBasicParsing 'http://itam:8080/api/agent/package' -OutFile ($p+'.zip'); Expand-Archive -Force ($p+'.zip') $p; & (Join-Path $p 'install.cmd') -ServerUrl 'http://itam:8080' -EnrollmentKey 'КЛЮЧ'"
```

Параметры `install.cmd`: `-ServerUrl`, `-EnrollmentKey`, `-IntervalHours`, `-IgnoreCertificateErrors`, `-Force`
(переустановить ту же версию), `-NoRun` (не отправлять сразу), `-Uninstall`.

### Через групповую политику (домен)

1. Распакуйте пакет без `agent.config.json` в `\\домен\NETLOGON\ITAM-Agent`.
2. Скопируйте шаблоны в центральное хранилище:
   `PolicyDefinitions\ITAM.admx` → `\\домен\SYSVOL\домен\Policies\PolicyDefinitions\`,
   `ru-RU\ITAM.adml` и `en-US\ITAM.adml` → в одноимённые подпапки.
3. Создайте GPO и привяжите её к OU с компьютерами:
   * **Конфигурация компьютера → Политики → Административные шаблоны → ITAM → Агент инвентаризации**:
     «Адрес сервера ITAM» = `http://itam.company.local:8080`, «Ключ регистрации» = ключ из ITAM;
     при необходимости «Интервал отправки данных», «Не проверять сертификат HTTPS сервера».
   * **Конфигурация компьютера → Политики → Конфигурация Windows → Сценарии → Автозагрузка** →
     добавить `\\домен\NETLOGON\ITAM-Agent\install.cmd`.
4. Компьютеры установят агент при следующей загрузке (или после `gpupdate /force` и перезагрузки) и сразу отправят
   данные.

Сценарий автозагрузки выполняется при каждой загрузке, но ничего не делает, если установлена та же версия агента.
Чтобы обновить агент на всех компьютерах, замените файлы в `NETLOGON\ITAM-Agent` новой версией.

Параметры GPO записываются в `HKLM\SOFTWARE\Policies\ITAM\Agent` (`ServerUrl`, `EnrollmentKey`, `IntervalHours`,
`IgnoreCertificateErrors`) и имеют приоритет над `agent.config.json`.

### Другие способы

Агент — обычный набор файлов, поэтому его можно распространять SCCM/MECM, Intune (Win32 app: команда установки
`install.cmd -ServerUrl … -EnrollmentKey …`, удаления `uninstall.cmd`, правило обнаружения — задача планировщика или
`C:\Program Files\ITAM Agent\ITAM-Agent.ps1`), PDQ Deploy и т.п.

## Настройки на сервере

**Агенты → Установка → Параметры** (право `agents.manage`):

| Параметр | По умолчанию | Описание |
|---|---|---|
| Создавать активы автоматически | вкл. | компьютер без совпадения получает новый актив (тип по корпусу: ноутбук LPT, системный блок PC, моноблок AIO, сервер SRV) |
| Регион / локация для новых активов | — | без региона компьютеры ждут ручной привязки |
| Обновлять данные активов | вкл. | имя компьютера, IP, MAC, а также доп. поля `cpu`, `ram`, `storage`, `gpu`, `os`; пустые серийный номер, модель и производитель заполняются |
| Интервал отправки | 4 ч | GPO может переопределить |
| «Не отвечает» через | 7 дней | такие компьютеры подсвечиваются и попадают в фильтр «Не отвечают» |
| Ключ регистрации | генерируется | смена ключа не отключает уже подключённые компьютеры |

## Работа с данными в ITAM

* **Агенты → Компьютеры** — список с фильтрами «Новый / Связан / Игнорируется / Не отвечают», поиск по имени,
  серийному номеру, пользователю, IP, инвентарному номеру.
* Карточка компьютера — оборудование, диски, сеть, мониторы, программы; действия: связать с активом, создать актив,
  отвязать, игнорировать, удалить (отзывает токен).
* **Агенты → Программы** — сводка установленного ПО по всем компьютерам (сколько установок, версии); по клику — список
  компьютеров с этой программой. Помогает сверять лицензии.
* Карточка актива — блок «Данные агента» и предупреждение, если за компьютером работает не тот сотрудник, которому выдан
  актив (или актив никому не выдан) — с кнопкой «Передать» / «Выдать».
* История актива — записи «Данные агента» о том, что изменилось (например, `ram: 8 → 16`).

## Безопасность

* Ключ регистрации нужен только для первого подключения; храните его как пароль. После утечки смените ключ в ITAM —
  подключённые компьютеры продолжат работать по своим токенам.
* Каждый компьютер получает собственный токен; в базе хранится только его SHA-256. Удаление компьютера в ITAM отзывает
  токен.
* Агент только отправляет данные и не принимает команд от сервера.
* Используйте HTTPS (см. INSTALLATION.md §9); «Не проверять сертификат» — только для внутренних самоподписанных
  сертификатов.
* Права: `agents.view` — просмотр, `agents.manage` — ключ, настройки, привязка и удаление.

## Диагностика

| Проблема | Что проверить |
|---|---|
| Компьютер не появился | `C:\ProgramData\ITAM Agent\agent.log`; доступность `http://сервер:8080/health` с компьютера |
| «Неверный ключ регистрации» | ключ в GPO / `agent.config.json` совпадает с ключом на вкладке «Установка» |
| Сценарий GPO не выполнился | `gpresult /h report.html`; доступ компьютера (не пользователя) к `NETLOGON\ITAM-Agent` |
| Компьютер «Новый», актив не создан | на карточке компьютера показана причина; задайте регион для новых активов или свяжите вручную |
| Не тот пользователь | у сотрудника заполнено поле «Логин (AD)» |

Ручной запуск и просмотр собранных данных без отправки:

```bat
powershell -ExecutionPolicy Bypass -File "C:\Program Files\ITAM Agent\ITAM-Agent.ps1" -Force -Verbose
powershell -ExecutionPolicy Bypass -File "C:\Program Files\ITAM Agent\ITAM-Agent.ps1" -Output C:\Temp\inventory.json
```

## API агента

| Метод | Описание |
|---|---|
| `POST /api/agent/register` | `{enrollmentKey, machineId, hostname, agentVersion}` → `{deviceId, token, intervalHours}`; 403 — неверный ключ |
| `POST /api/agent/inventory` | заголовок `X-ITAM-Agent-Token`, тело — отчёт (см. `AgentInventoryReport`); 401 `AGENT_NOT_REGISTERED` — зарегистрироваться заново |
| `GET /api/agent/package` | пакет агента без ключа |

Администрирование: `GET /api/agents`, `/api/agents/summary`, `/api/agents/{id}`, `/api/agents/{id}/software`,
`/api/agents/by-asset/{assetId}`, `POST /api/agents/{id}/link|unlink|create-asset|ignore`, `DELETE /api/agents/{id}`,
`GET /api/agents/software`, `/api/agents/software/devices?name=`, `GET|PUT /api/agents/settings`,
`POST /api/agents/settings/regenerate-key`, `GET /api/agents/package` (с ключом).
