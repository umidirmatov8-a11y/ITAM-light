# Подпись установщика и проверка загрузки

## Проверка скачанного файла

Рядом с установщиком лежит `ARC-Setup-<версия>.exe.sha256`. Сравните:

```powershell
Get-FileHash .\ARC-Setup-1.0.0.exe -Algorithm SHA256
Get-Content .\ARC-Setup-1.0.0.exe.sha256
```

Если файл подписан, «Свойства → Цифровые подписи» покажет издателя, а PowerShell —
`Get-AuthenticodeSignature .\ARC-Setup-1.0.0.exe` со статусом `Valid`.

## Подпись своей сборки

Нужен сертификат подписи кода (OV/EV) в файле `.pfx`.

```powershell
$env:ARC_SIGN_PFX = 'C:\keys\arc-code-signing.pfx'
$env:ARC_SIGN_PASSWORD = '<пароль>'
$env:ARC_SIGN_TIMESTAMP = 'http://timestamp.digicert.com'   # метка времени: подпись остаётся действительной после истечения сертификата
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

Подписываются `arc-backend.exe` (signtool из Windows SDK), `ARC.exe`, деинсталлятор и установщик
(electron-builder). В конце скрипт проверяет подписи и пишет SHA-256.

## CI

Задание `signing` в `.github/workflows/arc.yml`:

* если в секретах репозитория есть `ARC_SIGN_PFX_BASE64` (pfx в base64) и `ARC_SIGN_PASSWORD`, собирается и
  публикуется подписанный установщик (артефакт `ARC-Setup-signed`);
* иначе создаётся временный самоподписанный сертификат (живёт 2 дня, доверен только на этой машине CI),
  сборка подписывается им, и проверяется, что все три исполняемых файла подписаны и подпись `Valid`.
  Такой установщик не публикуется — это проверка того, что подпись работает.

## Честно о текущем состоянии

У проекта нет коммерческого сертификата, поэтому опубликованный установщик (`ARC-Setup`) **не подписан**:
Windows SmartScreen покажет «Неизвестный издатель» → «Подробнее» → «Выполнить в любом случае».
Целостность файла можно проверить по SHA-256. Как только сертификат будет добавлен в секреты, CI начнёт
выпускать подписанные сборки без изменений в коде.
