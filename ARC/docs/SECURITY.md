# Модель безопасности A.R.C.

## Принципы

1. **Каталог операций.** Выполняется только то, что описано в `backend/arc_backend/permissions/catalog.py`
   (23 операции) с типизированными, проверяемыми параметрами. Нет операции «выполнить команду».
2. **Нет оболочки.** Текст речи, документов, веб-страниц и ответов моделей не передаётся в shell.
   Процессы запускаются `subprocess.Popen([...], shell=False)` или `ShellExecute` для ярлыков,
   UWP и протоколов из белого списка (`steam`, `com.epicgames.launcher`, `ms-settings` …).
   Тест `tests/test_code_safety.py` статически проверяет отсутствие `shell=True`, `eval`, `exec`, `os.system`.
3. **Риск A/B/C.** A — выполняется сразу; B — подтверждение (кнопка или «да» голосом);
   C — только в окне A.R.C. с отметкой «Я понимаю последствия». Подтверждение одноразовое, с тайм-аутом,
   жестом / сценарием / моделью не подтверждается.
4. **Тестовый режим** (по умолчанию включён): операции B/C только записываются в журнал.
5. **Файлы** — только внутри разрешённых каталогов: путь нормализуется, символические ссылки разрешаются,
   `..` не выводит за пределы; зарезервированные имена Windows и опасные символы отклоняются;
   исполняемые файлы через «открыть файл» не запускаются.
6. **Запуск программ** — только из реестра. EXE вне `Program Files`, `%LOCALAPPDATA%\Programs` и т. п.
   добавляется только после явного подтверждения. Права администратора — только через UAC и категорию C.
7. **Разрешения меняются только из интерфейса** (`PUT /api/settings`). У роутера, модели, сценариев нет
   действия, изменяющего разрешения; модель не может переключить режим LOCAL/ONLINE.
8. **Аварийная остановка** (Ctrl+Alt+End, кнопка, «аварийная остановка» голосом) блокирует всё и
   сбрасывает ожидающие подтверждения.
9. **Журнал аудита** каждой операции: разрешена / подтверждена / отклонена / имитирована, источник
   (интерфейс, текст, голос, жест, сценарий, ИИ). Экспорт JSON/CSV.

## Локальный API

* Слушает только `127.0.0.1`, случайный порт.
* Случайный токен (256 бит) на каждый запуск, передаётся процессу ядра через переменную окружения и сразу
  удаляется из окружения ядра (дочерние программы его не наследуют).
* Отклоняются: запросы без токена; с заголовками `Origin` / `Sec-Fetch-*` (любой браузер, включая
  `fetch` со сторонних сайтов); с чужим `Host` (DNS rebinding); POST/PUT с телом не `application/json`.
* Интерфейс не обращается к API напрямую: renderer изолирован (`sandbox`, `contextIsolation`), запросы идут
  через main-процесс по белому списку маршрутов (`app/electron/routes.ts`); `/api/shutdown` недоступен из UI.
* Electron: запрет навигации, новых окон, `<webview>`, всех запросов разрешений браузера; строгий CSP.

## Сеть и данные

* LOCAL — A.R.C. не обращается к интернету (тесты проверяют отсутствие внешних соединений).
* ONLINE — только по явной команде пользователя. Главный выключатель «Разрешить онлайн-функции» полностью
  запрещает ONLINE. Все запросы идут через `OnlineClient`, который в момент запроса проверяет режим, допускает
  только https (и SearXNG на этом компьютере), не даёт перенаправлению уйти на http, ограничивает число запросов
  в минуту, время ответа и размер (2 МБ) и записывает каждый запрос в журнал аудита (сервис и адрес, без текста
  запроса). Модель не может включить ONLINE (`mode.set` запрещён для источника «ИИ»).
* Текст из интернета — данные: заголовки и фрагменты очищаются от HTML, ссылки принимаются только http(s);
  при сводке и при написании документа модель получает их как пронумерованные источники с указанием игнорировать
  инструкции внутри; результат только показывается или записывается в документ, но не превращается в действия.
* Ключи API (Brave Search) хранятся в Диспетчере учётных данных Windows (`ARC/online/<сервис>`, шифрование
  DPAPI для текущего пользователя) — не в коде, не в `arc.db`, не в логах; API отвечает только «ключ есть/нет».
* Документы: создание файла — категория B (подтверждение, тестовый режим имитирует); папка проверяется по
  разрешённым каталогам; файл пишется во временный, проверяется чтением и только затем переименовывается;
  существующие файлы не перезаписываются; в XLSX сгенерированный текст никогда не становится формулой.
* Видео, аудио и снимки не сохраняются и не отправляются. Микрофон открывается только во время прослушивания;
  при выключенном переключателе «Микрофон» не открывается вовсе. Телеметрии нет.
* Голос не обходит разрешения: распознанный текст проходит тот же роутер и Permission Manager; в режиме
  постоянного прослушивания нужна фраза со словом активации и уверенность выше порога; критические действия
  голосом не подтверждаются.
* Жесты: камера открывается только при включённых жестах и разрешённой камере; кадры только в памяти, превью —
  лишь в режиме проверки камеры (2 минуты); жесту можно назначить только действие категории A с отметкой
  gesture_allowed — проверяется при сохранении настроек и повторно Permission Manager при срабатывании.
* Локальная языковая модель только предлагает действия: ответ разбирается как JSON по схеме, каждое действие
  проверяется по каталогу (без `mode.set`, `app.launch_admin`, `process.terminate`), параметрам и реестру, затем
  проходит Permission Manager с источником «ИИ»: B/C — подтверждение пользователя (модель подтвердить не может),
  по желанию — подтверждение и для A. В системном промпте текст пользователя объявлен данными; CI проверяет
  реальную модель на попытки «игнорируй правила / выполни PowerShell / выключи без подтверждения».
* Модели загружаются только по нажатию пользователя после показа размера; загрузка атомарна, архивы
  проверяются на выход за пределы каталога (zip-slip); Piper запускается списком аргументов, текст — через stdin.

## Ограничения (честно)

* Процессы того же пользователя Windows теоретически могут прочитать память A.R.C.; защита локального API
  рассчитана на браузеры и других пользователей, а не на вредоносное ПО с правами пользователя.
* Установщик и EXE не подписаны цифровой подписью — SmartScreen может показать предупреждение.
