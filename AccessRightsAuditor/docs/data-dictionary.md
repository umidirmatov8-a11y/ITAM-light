# Словарь данных

Полная схема описана в `database/migrations/001_init.sql`. Все первичные ключи — UUID (кроме `activity_logs.id` — bigserial). Даты действия хранятся в типе `date`, метки времени — в `timestamptz`.

| Таблица | Назначение | Ключевые ограничения |
|---|---|---|
| users, app_roles, app_role_permissions, user_role_assignments, sessions | Учётные записи и RBAC приложения | `username` уникален; в сессиях хранится только хеш токена |
| app_settings | Параметры (тайм-ауты, лимиты, политика критичности) | |
| departments, positions | Оргструктура | `code` уникален |
| employees | Кадровая идентичность и статус | уникальность по (`hr_source`, `employee_key`); `valid_to` — дата увольнения; `previous_*`, `transferred_at` — перевод |
| systems | Банковские системы | `owner_user_id` — владелец (ограничивает видимость находок) |
| access_roles, modules, operations | Роли и атомарные операции | уникальность кода в пределах системы/модуля; `operations.risk_level` |
| role_operations | Стандартный состав роли | |
| aliases | Таблица нормализации разных написаний | уникальность (тип, система, lower(alias)) |
| matrix_versions, matrix_rules | Версионированная матрица | правила утверждённой версии неизменяемы (триггер); NULL в области = «любое» |
| sod_rules, sod_rule_items | SoD-конфликты (стороны 1..N, элементы — операции или роли) | компенсирующий контроль требует указания, кем он утверждён |
| exceptions | Согласованные исключения | не удаляются, только отзываются |
| audit_runs | Запуски аудита и снимок версии правил | контрольные суммы пакета, матрицы, правил, результатов |
| import_batches, import_rows | Происхождение данных: файл, SHA-256, маппинг, сырые строки и ошибки | |
| access_snapshots | Атомарные фактические назначения | уникальность (`audit_id`, `access_key`); защищены после завершения аудита |
| audit_findings, finding_comments | Находки и их обработка | `finding_key` — стабильный ключ для сравнения |
| audit_comparisons, comparison_items | Сравнение двух снимков | |
| reports | Сформированные отчёты (SHA-256, фильтры, автор) | |
| activity_logs | Журнал действий | UPDATE/DELETE запрещены триггером |

## Стабильный ключ назначения (`access_key`)

`табельный номер | код системы | логин | код роли | код модуля | код операции` — всё в нижнем регистре. Для сотрудника используется канонический табельный номер из справочника, с учётом алиасов. Нераспознанные значения помечаются префиксом `?`; такие записи при сравнении попадают в список неоднозначных.
