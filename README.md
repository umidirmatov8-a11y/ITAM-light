# ITAM-light

Лёгкое локальное приложение для учёта выдачи/возврата ноутбуков и компьютеров с формированием подтверждающих документов на каждое действие.

## Цели
- Учитывать только устройства типов: **компьютер, ноутбук, моноблок, мини‑ПК**.
- Хранить минимум полей: **имя компьютера**, **владелец**, **филиал**, **дата приёма**, **дата возврата**, **дата передачи другому ответственному**.
- Формировать документ при каждом событии:
  - выдача сотруднику — *акт приёма‑передачи*;
  - возврат — *акт возврата*;
  - смена филиала или ответственного лица — *акт передачи*.
- Локальный запуск в виде **.exe** (Windows) и база данных **PostgreSQL**.
- Возможность **бэкапа** данных на сервер.
- **Авторизация** пользователей.

## Предлагаемая архитектура (MVP)
- **UI**: локальное desktop‑приложение (например, Electron или Tauri) с упаковкой в `.exe`.
- **Backend**: локальный сервис (Node.js/Express или .NET) с подключением к PostgreSQL.
- **Хранилище**: PostgreSQL (локально или удалённо), резервное копирование `pg_dump`.
- **Документы**: шаблоны актов в PDF (генерация из HTML + CSS).

## Минимальная модель данных
### entities
- **devices**
  - `id` (uuid)
  - `name` (text) — имя компьютера
  - `type` (enum) — `computer | laptop | monoblock | mini_pc`
  - `owner` (text) — владелец/ответственный
  - `branch` (text) — филиал
  - `received_at` (date) — дата приёма
  - `returned_at` (date, nullable) — дата возврата
  - `transferred_at` (date, nullable) — дата передачи другому ответственному
- **documents**
  - `id` (uuid)
  - `device_id` (uuid)
  - `doc_type` (enum) — `handover | return | transfer`
  - `created_at` (timestamp)
  - `file_path` (text) — путь к PDF
- **users**
  - `id` (uuid)
  - `email` (text, unique)
  - `password_hash` (text)
  - `role` (enum) — `admin | user`

## Основные сценарии
1. **Выдача сотруднику**
   - Создать запись устройства.
   - Сформировать акт приёма‑передачи (PDF).
2. **Возврат**
   - Обновить `returned_at`.
   - Сформировать акт возврата.
3. **Передача** (смена филиала/ответственного)
   - Обновить `owner/branch`, записать `transferred_at`.
   - Сформировать акт передачи.

## Бэкап и восстановление
- **Бэкап**: `pg_dump --format=custom --file=backup.dump <db_name>`
- **Загрузка на сервер**: SFTP/SSH в запланированном задании.
- **Восстановление**: `pg_restore --clean --dbname=<db_name> backup.dump`

## Авторизация
- Логин/пароль с хранением хеша (bcrypt/argon2).
- Роли: администратор (полный доступ), пользователь (операции с устройствами, документы).
